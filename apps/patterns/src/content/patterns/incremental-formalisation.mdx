Content that entered informally has started to repeat itself: a label applied again and again, near-synonyms circling one meaning, prose that behaves like a list, a note field everyone fills the same way. The structure is visibly there — but it was never declared, because demanding a schema up front was rightly refused while the vocabulary was still moving.

Incremental formalisation promotes structure only after the content has earned it. The system recognises what recurs and offers to formalise — merge these two labels, turn this recurring mark into a field, treat this prose as a table — and the actor accepts, defers, or ignores. Structure stays optional and reversible: gained in place when it starts paying, shed in place when it stops.

The failure this designs against is documented: demanded formality fails on cognitive overhead, tacit knowledge, premature structure, and situational structure — actors either refuse the schema or fill it with guesses. The remedy is the same in the research and in shipping tools: let information in informally, recognise undeclared structure, and formalise by offer.

## Examples

- A search refined by hand, offered back as a saved filter or smart folder
- Two near-synonym labels offered a merge; a recurring label offered as a field
- Prose recognised as a list or table and offered the conversion, reversibly — the block-editor instance
- A spreadsheet range recognised as a table and offered headers and types
