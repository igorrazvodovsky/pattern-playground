* * *

**People read a rule or a replace pattern and believe they know what it will do. Reading does not show what it matches. They find out when it runs, and by then the mistake has landed on every item at once.**

A one-off edit, such as a find-and-replace, a batch rename or a mail merge, acts on items that are all in view, so the dry run can show all of them. A standing rule, such as a mail rule or a home automation, acts on items that have not arrived yet, so the dry run can only use a sample: replay the rule over what already happened, run it alongside the rules already in place, or show the items that only just match or miss. The sample decides what the actor learns, and people who pick it themselves leave out the edge cases. [Action consequences](/patterns/action-consequences) says when a bulk action needs a dry run at all.

Therefore,

**Before a rule or a bulk edit runs, run it against items the actor knows and show what would happen to each, changing nothing. Where every item is in view, show all of them as a before and after; where they are not, use past items and the existing rules, and let the actor add an item of their own. Keep the rule and the result side by side, and run again after each edit.**

The dry run says nothing about items it did not run on. When the sample is small, say so, rather than let the dry run look like a pass.
