* * *

**The actor needs a past state of their work, not just the last few actions. Undo has ended with the session, the log says what happened without letting them return to it, and copying files to keep old states produces a folder of "final-v2-really-final" that nobody can tell apart.**

Three things pull against each other:

- *Coverage against legibility.* Keeping every state means nothing is lost, but an unbroken stream of autosaves is as hard to navigate as no history. Figma and Google Docs both keep automatic checkpoints and let the actor name the ones that matter, with a filter that shows only the named ones.
- *What a version contains.* A version can hold the document alone or the document with its comments, settings, and permissions. In Google Docs, comments are not stored with versions, so restoring an old one brings back the text without the conversation about it.
- *Restoring without losing the present.* Restoring replaces the current state, which is exactly the loss the history exists to prevent. Figma's restore adds a checkpoint of the state it replaces before it restores, so the restore can itself be undone.

The pattern costs storage and a retention policy. It also creates a second place where content lives: text removed from the current version is still readable in earlier ones, which matters wherever the actor expects removal to be final.

Therefore,

**Keep past states of the work beyond the session, and let the actor give names to the moments that matter. Show named versions apart from automatic checkpoints, let the actor compare any version with the current one before restoring it, and make restoring a new version rather than an overwrite, so the state it replaced stays available. State what a version includes and how far back the history goes.**

Naming every version adds work the actor will not do, so automatic checkpoints carry most of the history, and names are reserved for publishes, hand-overs, and states the actor chooses to mark.

## In practice

- *Automatic checkpoints:* taken at intervals or on events (a session ending, a connection dropping), unnamed by default.
- *Named versions:* created on purpose, or by naming an existing checkpoint; often created by the system at a publish or release.
- *Browse and preview:* a list or timeline of versions, each opening read-only, usually with changes highlighted against its neighbour.
- *Restore and copy:* restoring makes the past state current; copying makes a new item from it and leaves the current state alone.
- *Retention:* how far back the history reaches, often tied to a plan or a storage limit, and stated to the actor.
