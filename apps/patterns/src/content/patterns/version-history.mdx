* * *

**When work is continuously overwritten, the actor cannot easily return to how it stood earlier. They hesitate to make bold changes, or they scatter duplicate copies across folders trying to keep old drafts safe.**

Four things pull against each other:

- *Keeping everything against finding anything.* Saving every moment in the background means nothing is lost, but an unbroken list of timestamps is as hard to read as no history at all. Letting the system keep the background trail while the actor names the moments that matter — and filter down to those named versions — keeps the history both complete and readable.
- *Knowing what comes back.* People assume an older version brings back the whole work as they remember it, yet comments, settings, or permissions are often left out (in Google Docs, restoring an earlier draft brings back the text without the comments).
- *Going back without losing where you are.* Returning to an older version replaces the current work, which can feel as risky as the mistake that sent the actor looking back. In a document history such as Figma, keeping the replaced state as its own version makes going back safe to undo. In a conversation with an agent, stepping back to an earlier turn discards the turns after it; when the actor wants to keep both lines, [branching](/patterns/branching) holds them apart.
- *Safety against forgetting.* Old versions make deleting easier to live with because removed passages can still be found, yet content deleted from the current work stays readable in earlier versions. Where privacy or policy requires something to be truly gone, retention limits and removal have to reach into past versions too (see *Enforcing the limits on memory* in [memory and continuity](/sequences/memory-and-continuity#forgetting)).

Therefore,

**Keep earlier versions of the work automatically, let the actor name milestones so they can filter past the noise, and let them [compare](/patterns/comparing) and return to any point in the trail. Be explicit about what a version includes, how long it is kept, and what happens to the current work when the actor steps back.**

## In practice

- *Taking only a piece back:* when the actor only wants one deleted paragraph or element rather than the whole earlier version, letting them copy out of the read-only preview saves them from undoing newer work around it.
- *Stepping back in an agent conversation:* an agent can change several files in a single turn, so checkpoints tie each turn to the files it touched. Stepping back to an earlier checkpoint returns both the conversation and the files to that moment by dropping the later turns; because the actor chose the exact point to return to, doing so directly avoids nagging unless [action consequences](/patterns/action-consequences) calls for a safeguard (as in VS Code's file-revert prompt), and [branching](/patterns/branching) keeps the later turns when both lines matter.

## Resources & references

- Figma Learn: [View a file's version history](https://help.figma.com/hc/en-us/articles/360038006754-View-a-file-s-version-history) — checkpoints every 30 minutes, named versions, restore as a non-destructive change, retention by plan
- [Version history essentials for Google Docs, Sheets, and Slides](https://www.techrepublic.com/article/version-history-essentials-for-google-docs-sheets-and-slides/) — naming versions, showing only named versions, comments not kept with versions
- Edwards & Mynatt (1997) [Timewarp: techniques for autonomous collaboration](https://faculty.cc.gatech.edu/~keith/pubs/autonomous-html/autonomous.html), CHI '97 — making time explicit and editable in the interface, with divergent histories kept visible
- VS Code: [Chat checkpoints](https://code.visualstudio.com/docs/copilot/chat/chat-checkpoints) — restoring a checkpoint removes the later requests and returns the files to that point, after a confirmation
- Grossman, Matejka & Fitzmaurice (2010) [Chronicle: capture, exploration, and playback of document workflow histories](https://www.research.autodesk.com/?p=1833), UIST '10 — linking a document's content to the part of its history that produced it
