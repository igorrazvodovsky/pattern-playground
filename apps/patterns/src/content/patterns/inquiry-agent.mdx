The agent asks the user a question to which it does *not* know the answer in order to capture new information.

1. A: Ask for a specific piece of information (slot).
2. U: Provide value → A: Confirm/store.
3. U (Optional): Sequence closer.

This primitive is the building block for [question-driven dialogue](/patterns/conversation#question-driven-dialogue), where chains of agent inquiries prompt human thinking and elaboration.

## Repair affordances
Repeat the question; paraphrase; example of valid input; define technical terms.

## Metrics
Drop-off per slot; correction rate; time-to-complete; data validity rate.

## In practice

### Several questions at once

When the agent needs more than one value before the work can go on, it can ask them together as a short questionnaire in its turn: one question at a time, with the position shown and the answers sent as one reply. The ranked-candidates case fits fixed choices with a field for an answer of the actor's own, and a value the agent could default becomes a question the actor can skip, with its description saying what skipping leaves in place. The confirmation still comes from the agent's next message, which says what it did with the answers.
