* * *

**Asking an actor to retype structured personal data—addresses, credentials, payment details, or profile fields—repeats work the browser or application already holds and invites transcription errors. Yet silent pre-filling carries asymmetric costs: stale personal values slip past review more easily than generic guesses, clearing a wrong pre-fill takes more effort than typing from scratch, and filling a field silently shows what the system holds about the actor in a place they had not asked the question.**

The source of the value changes what the actor notices and controls. Browser and password-manager autofill keeps storage under the actor's control and signals which tool supplied the values; application-side autofill draws silently from backend records the actor may not realise the system kept.

Therefore,

**Populate structured fields from stored values only when confidence is high and the actor can tell at a glance which fields were filled automatically. Preserve standard semantic `autocomplete` hints so browsers and password managers can supply and manage the actor's data, distinguish pre-filled values visually from typed text, indicate the source when the application fills from its own record, and keep every filled value easy to clear or overwrite before submission.**

Never let hidden or off-screen fields receive autofilled data—they can be filled silently and read by script before the actor ever submits the form—and do not break browser autofill with custom split inputs or non-standard field names.
