Work the actor started or delegated runs out of sight: a build, an import, a scheduled job, an agent working through a task. The actor wants to know whether it is on track. Watching it live costs their whole attention, and opening its full record costs a search. Both cost more than the question deserves, so the actor either checks too often or not at all.

Run status answers the question at a glance. It shows whether the run is live, stalled, finished, or failed, what it has produced so far, and when it acts next. A run waiting for its next trigger still shows that it is live, so that a dead run never looks like a waiting one. When the glance suggests a problem, it leads straight into the record at the point it describes.

## Where it is practised

- Continuous integration services that show each pipeline's state as a badge and a list of stages, each opening into its log.
- File transfer and sync tools that show progress, remaining time, and a stalled state in the menu bar or task bar.
- Scheduled job dashboards that show the last run, its result, and the next run time.
- Coding agents that show their current step and elapsed time in a status line, opening into the full transcript.
