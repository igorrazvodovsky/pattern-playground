The work has produced something that now matters more than the transaction that
produced it — a document, a decision, a piece of code — and that transaction is the
only place it exists. It has no name of its own, no address to link to, and nothing to
reopen; finding it again means finding the exchange it happened in and scrolling.

Extraction gives it an identity. The thing is lifted out of its host and put somewhere
it can be named, linked, versioned, and returned to. What changes is not where it sits
on the screen but that it now exists independently of whatever made it.

## Where the move arises

Only where the host is *possessive* — where what it produced has no identity apart from
it. Most output is born addressed: a document made in a documents application already
has a name, a place in a list, and a URL, and there is nothing to extract. Conversations,
comment threads, search sessions, and message streams are possessive in this way. They
hold what happens inside them as content rather than as things.

The condition is worth stating because it bounds the pattern. A design that keeps
reaching for this move where the output is already addressed has misread what
its host does.

## Instances

- a comment turned into an issue
- a message turned into a task
- a hand-refined search turned into a saved view
- an attachment turned into a file in the shared drive
- generated output turned into its own document — the vivid instance, and the one the
  move was first noticed in, but not the definition
