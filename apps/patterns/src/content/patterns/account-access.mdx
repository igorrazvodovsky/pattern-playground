* * *

**Actors need to establish an identity or assert an existing one to access private workspaces, but access interfaces frequently ask for more than identity requires, break browser autofill, or combine registration and sign-in into clever ambiguous steps that confuse actors.**

### Forces

- *Distinct paths vs clever unification*: attempting to combine sign-in and registration into a single adaptive input field (asking for email first, then dynamically branching to sign-in or register) confuses password managers, breaks browser autofill, and leaves actors uncertain whether they already hold an account.
- *Minimal entry vs collected detail*: every field beyond an identifier and a credential slows registration, and much of what is asked for up front could be asked later, when it is needed.
- *Persistent presence vs shared device risk*: remembering credentials and preserving session state across visits reduces daily friction, but risks exposing private workspaces on public or shared machines.



Therefore,

**Provide an explicit, predictable access path: keep registration visually distinct from sign-in, let browsers and password managers fill both, and ask only for an identifier and a credential.**

Ask for other details later, at the point the artifact needs them.

## In practice

### Returning access and session persistence

For returning actors, respect saved credentials and browser autofill. Offer an explicit "Remember this device" option that extends session lifetime appropriately. When a session expires during active work, allow the actor to re-authenticate inline via a modal or overlay so their current scroll position, unsaved input, and view context are not lost.

### Offering more than one credential

When the artifact offers a password alongside passwordless access or federated identity, show the options on the same screen in a fixed order, starting with the one most actors will use, and use the same order on sign-in so a returning actor finds the one they used before. After sign-in, let the actor add or remove credentials from their account settings.
