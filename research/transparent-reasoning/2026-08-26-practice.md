# Practice evidence: how products surface reasoning — 2026-08-26

Companion to `2026-08-26.md` (literature). Vendor documentation and product docs, fetched live on the date above; kept separate so the two provenance classes stay distinguishable. Reasoning display is changing fast — treat every behaviour below as of this date.

## The visible trail is a rendered artefact, not the trace

Three of the four major vendors withhold the raw trace and display a summary produced by something other than the model that reasoned. This is the clearest thing in the whole gate, and it is stated by the vendors themselves.

*Anthropic* ([platform.claude.com/docs — extended thinking](https://platform.claude.com/docs/en/build-with-claude/thinking)): what you see "is never the raw chain of thought"; no API setting returns it, with misuse prevention as the stated rationale. "Summarization is processed by a different model from the one you target in your requests. The thinking model does not see the summarized output." Billing follows the hidden work, not the display: "You're charged for the full thinking tokens generated by the original request, not the summary tokens." On the 2026 model line the API default is `display: "omitted"` — an empty thinking field, with faster time-to-first-text-token as the cited benefit — so *visible reasoning is an opt-in product decision, not the default surface*. And the trail is read-only at the platform boundary: full thinking is encrypted into an opaque `signature`, and thinking blocks passed back in a conversation cannot be edited, reordered, or partially dropped; the API rejects modified blocks.

*OpenAI* ([Learning to reason with LLMs](https://openai.com/index/learning-to-reason-with-llms/), Sep 2024; [reasoning guide](https://developers.openai.com/api/docs/guides/reasoning), fetched 2026-08-26): does not show raw chains of thought, displays a model-generated summary instead. The announcement names three weighed factors for hiding it — user experience, competitive advantage, and preserving chain-of-thought monitoring — so the decision is not framed as purely a safety argument. The monitorability argument is the interesting one for design: keeping the trace monitorable requires leaving it *untrained* on policy compliance and user preferences, which means a trace fit for showing to actors and a trace fit for monitoring pull in opposite directions. OpenAI hedges the claim itself — reading the CoT reveals the process only "if that CoT is faithful and legible". In the API, the summary is opt-in via a `summary` parameter with `concise`/`detailed`/`auto` granularity, so *the verbosity of the visible trail is a product configuration rather than a property of the computation*. Reasoning tokens are metered and consume context while remaining invisible; in stateless mode the trace round-trips through the client's own payload as an `encrypted_content` blob it cannot read.

*Google* ([Gemini API — thinking](https://ai.google.dev/gemini-api/docs/thinking), last updated 2026-08-17): same shape. Full internal thoughts are generated, only a separately generated summary is emitted, and the customer is billed for the unseen full thought tokens. The actual reasoning state comes back as an encrypted "thought signature" no viewer can read. Summaries are opt-in (`thinking_summaries`, values including `auto` and `none`), and a thought block can arrive carrying a signature but *no summary text* — so the visible trail can be empty while reasoning did occur, and developers are told to handle that case. Clients managing their own history must resend every thought block byte-for-byte and must not edit them: the trace is required conversation state, not display material.

*DeepSeek* ([thinking mode](https://api-docs.deepseek.com/guides/thinking_mode)) is the exception on access. Chain-of-thought comes back to developers in a dedicated `reasoning_content` field alongside the answer `content`, in both streaming and non-streaming responses, emitted before the final answer, with depth exposed as a `reasoning_effort` setting. The same field is discardable in plain chat and *mandatory* in agentic tool loops — when a request carries `tools`, `reasoning_content` must be passed back on every subsequent turn. Thinking mode also disables the usual sampling controls (`temperature`, `top_p`, `presence_penalty`, `frequency_penalty`).

Three consequences for the pattern, all of them design constraints rather than model facts:

- The thing on screen is a second-hand rendering. Better summarisation improves the rendering; it does not touch whether the underlying trail described the computation (literature note, Gap A).
- Length on screen carries no information about work done — Anthropic and Google both bill the hidden full trace, and OpenAI's verbosity is a setting. Any interface treating trace length as effort is reading a display parameter.
- Editing the visible trail is foreclosed at the platform level by two of the three major APIs. Research systems that make reasoning editable are operating on a local artefact, which matches Hippo's own disclaimer in the literature note.

## Agentic tools show actions, not reasoning

Devin ([session tools](https://docs.devin.ai/work-with-devin/devin-session-tools)) is the useful contrast case. Its visible trail is a log of *executed actions* — shell commands, code edits, browser activity — unified in a Progress view, drillable at step granularity with command outputs inline, so the actor can verify each step's effect without leaving the session. That is tool-call provenance, not chain-of-thought display. Cognition frames it explicitly as a monitoring surface for early course correction, telling actors to intervene when the trail reveals a wrong direction.

Intervention granularity is coarse: a session-level interrupt plus human takeover in the IDE — halt the whole run, not edit or branch a step. One nuance worth noting: stopping a generated response mid-answer in a side chat is decoupled from halting the agent's work.

This distinction is probably the most useful thing in the practice half for the library. In agentic products, the trail an actor actually reads is a record of what the system *did*, which is verifiable against the world, rather than an account of what it *thought*, which is not. Those are different objects with different epistemics, and in this library they are already different patterns — `activity-log` holds the first.

## Takeaways for the pattern page

- Lead the forces with the rendering gap, sourced to the vendors' own words rather than to inference. "The reasoning model does not see the summarized output" is the whole problem in one sentence, and it is Anthropic's sentence.
- Add a form the page does not name: *reasoning hidden by default*. The current page assumes display is the design choice; on the newest APIs, omission is the default and display is opt-in.
- The action/reasoning split deserves a named distinction on the page — action traces are checkable against effects, reasoning traces are not. It also sharpens the boundary with `activity-log` and `plan-preview`.
- Drop any framing that treats visible trace length as a signal of effort or difficulty. Both the vendor docs and Kambhampati et al. (literature note) contradict it, from opposite directions.
