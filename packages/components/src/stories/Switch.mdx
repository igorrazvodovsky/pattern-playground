# Switch

Flip a setting whose effect should apply the moment the actor commits, with no intervening submit step.

<Canvas>
  <Story of={SwitchStories.Switch} />
</Canvas>

## When to reach for a switch over a checkbox

Immediate-effect settings — notifications on/off, dark mode, feature toggles — belong on switches. Deferred-commit form fields belong on checkboxes.

## Accessibility

`pp-switch` follows the [WAI-ARIA APG switch pattern](https://www.w3.org/WAI/ARIA/apg/patterns/switch/):

- `role="switch"` so assistive tech announces "on/off" rather than "checked/unchecked".
- `aria-checked` is strictly `"true"` or `"false"` — switches do not have a mixed state. If a third state is needed, the answer is a different control, not an extended switch.
- Space toggles the switch (native checkbox behaviour, preserved). Enter does not toggle, by APG convention.
- The accessible name comes from the `label` or `labelledby` properties.

## Related patterns

- [Checkbox](../?path=/docs/primitives-checkbox--docs) — same binary-state input, different commit timing
- [Button](../?path=/docs/primitives-button--docs) — for one-shot actions where state isn't carried forward
- [Morphing controls](../?path=/docs/components-morphing-controls--docs) — when each state needs a distinct label or affordance (Follow/Unfollow, Start/Stop), a morphing control is the better fit
