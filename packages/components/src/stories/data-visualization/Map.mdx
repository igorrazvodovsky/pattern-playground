> 🗺️ *Fun meter: 3/5*. Tiles and pins are settled technology, so the engineering isn't the interesting part. The tension is: a map is the one picture a reader understands with no legend, and also the one that shuts out anyone who can't see it. The companion list resolves both at once — it's the navigation feature and the accessibility story in the same object. That double duty is what's worth thinking about.

# Map

When the question is *where is it*, a map answers on ground the reader already knows: named places sit on a base they can pan and zoom until the arrangement makes sense.

This is the located-point sibling of the <PatternRef slug="data-visualization">chart territory</PatternRef>. Where a [choropleth](../?path=/docs/data-visualisation-choropleth--docs) shades whole regions by a quantity, the map plots discrete things — offices, incidents, stops, stores — each at its own coordinate. Position here is not a channel you assign; it is the datum. The base tiles exist only to make that position legible: a coastline or a road tells the reader *near what*, which a bare scatter of dots never could.

## Variants

### Map with a companion list

<Story of={MapStories.Default} />

Every place is both a pin on the map and a row in the list. The two are one selection: choosing a row frames and opens that pin, clicking a pin marks its row. This is the default because it is the honest one — the map alone is unreadable to a screen reader, and the list alone loses the geography.

### A place already in focus

<Story of={MapStories.Preselected} />

Setting `selected-id` opens the view on a specific place. Use it when the map arrives already answering a question — a search result, a row the reader clicked through from a table.

### Map only

<Story of={MapStories.MapOnly} />

Dropping the list suits a display already surrounded by context — a dashboard tile, a card whose caption names the places. Reach for it deliberately: without the list, the accessible route to the data goes with it, so this variant needs its equivalent supplied elsewhere on the page.

### A single point

<Story of={MapStories.SingleLocation} />

Given a centre and zoom, the map settles on one place rather than fitting them all — the detail view of an address, the *you are here* of a venue.

## Data

The component takes one flat list; there is no separate geometry to join:

- `locations` — one `{ id, name, lat, lng, description? }` per place. `lat`/`lng` are decimal degrees; `name` and `description` show in the pin's popup and the list row.

With no `center`, the view fits every marker. With one, it holds that point at `zoom`. Nothing assumes these are offices — swap in sensor readings, delivery stops, or property listings and the same element plots them.

## Tiles & attribution

The base layer is raster tiles, OpenStreetMap by default, fetched over the network — so a story with no connection shows the pins over blank tiles, and most providers *require* the attribution the map carries in its corner. Point `tile-url` and `attribution` at another provider to change the base; everything above the tiles stays the same. Vector tiles, clustered pins, and drawn regions are the obvious next layers, and Leaflet supports them, but they are out of scope here.

## States

### Loading

Tiles fade in as they arrive; pins are placed immediately from coordinates, so the reader sees the answer before the basemap finishes painting.

### Empty

With no locations the map still draws, centred on the world — the frame the reader is about to fill, rather than an error.

### Resized

The map recovers from a late layout — revealed in a tab, dropped into a flex row — by re-measuring its container, so tiles stay aligned instead of smearing.

## Accessibility

A map is a picture, and a picture excludes anyone who cannot see it. The companion list is the equivalent, not an add-on: it carries every place as real text, in the reading order of the data.

### Screen reader support
- The list is a `listbox`; each place is an `option` whose selected state tracks the map.
- Pins are decorative to assistive technology — the list is the source of truth, so nothing is announced twice.
- Each pin still carries a native popup, so a sighted pointer user gets the name and detail on click.

### Keyboard navigation
- Tab: reach the list, then the map (the base map's own arrow-pan and zoom take over once it is focused).
- Arrow keys / Home / End within the list: move between places.
- Enter / Space: select the focused place — framing its pin and opening its popup (emits `pp-map-select`).
